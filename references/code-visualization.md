# 代码可视化：让读者看见原理

适用于绘制函数、空间关系、数值过程或参数影响。目标是帮助读者建立可验证的直觉，而不是给每篇笔记加装饰图。

## 先定教学问题，再定图形

先写清“读者看完这张图应该理解什么”，然后选择能回答它的表示：

| 教学难点 | 可用表达 | 观察与解释重点 |
|---|---|---|
| 参数怎样影响系统响应 | 相同坐标下比较几组参数，或响应曲线与参数对应的多面板图 | 哪些量保持不变，峰值、收敛或振荡怎样变化，原因是什么 |
| 阈值怎样改变筛选结果 | 固定输入，展示 `0.3`、`0.6`、`0.9` 等经过推敲的阈值下结果；具体值按问题选择 | 同一对象为何保留或排除，阈值方向是否与算法一致 |
| 矩阵、卷积或离散运算难以想象 | 用小规模具体输入展示取值、局部计算和结果，颜色或箭头连接对应位置 | 一个输出值如何从输入算出，图与手算能否对应 |
| 优化过程或几何变换 | 等高线与轨迹、变换前后同一组点、局部放大 | 每一步为什么沿这个方向，步长或变换参数怎样改变结果 |

这些是设计思路，不是每篇都要绘制的模板。题目中的数据不适合上述数值时，不机械照搬。

## 用图形成一个小型学习单元

1. **图前提问**：用一两句话提示观察目标，可让读者先预测一种变化。
2. **实际图像**：显示必要的参数、单位、坐标、步骤或对照，颜色含义保持一致。对比图尽量使用相同尺度；若刻意改变尺度，说明原因。
3. **读图解释**：指出图中确实可见的现象，并解释它与正文原理、公式和例题的对应关系。不要让图承担未说明的逻辑跳步。
4. **回到应用**：说明这种观察怎样帮助计算、调参、判断边界或避免误区。模拟数据不能冒充真实实验；有限参数示例不能当成一般性证明。

例如讲阻尼比时，不只是贴三条不同颜色的曲线。应说明比较时固定了什么，读者该看超调、振荡还是趋于稳态的过程，再用实际计算结果解释所画参数下为什么出现这些差别。

## 生成与嵌入

- 优先利用现有运行环境；Python 绘图或可直接生成的 SVG 均可。缺少库时先尝试现有替代方式，不把安装依赖、联网加载脚本或启动服务当作默认授权。
- 将脚本、可复现的参数和导出的图片放在当前库约定的附件位置，通过实际可解析的路径嵌入笔记。使用随机数据时固定种子；绘图代码不能改动源课件。
- 选择在普通笔记宽度下可读的尺寸和字号。检查中文字体、数学符号、坐标、图例和颜色区分；不用只在白底／深色背景之一才可辨识的低对比文字。
- 小数刻度和标注保留前导零，如 `0.9`、`-0.2`。使用绘图库默认格式前先检查实际输出；需要时显式设置格式化器，不改变数值来迁就标注。
- 默认以 SVG 或 PNG 提供无需运行代码就能读的结果。只有时间过程确实重要且现有工具支持时才增加动画；交互版本是补充，不是静态解释的替代品。

## 核验完成标准

- 运行脚本确认实际生成文件；手算或用独立数值检查核对代表性点、边界与关键结果。
- 打开导出图检查画面。SVG 可在现有能力允许时渲染预览，若无法检查实际画面则报告限制，不把“文件已存在”当作视觉验收。
- 检查标签无缺字、内容无裁切、曲线或对象未误配、图中数值与正文一致、笔记引用指向真实图片。
- 没有运行的代码只是待运行代码，不能声称已经生成图；没在 Obsidian 检查过则不能声称客户端渲染已验证。
